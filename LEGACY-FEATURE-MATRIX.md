# Bat Melech Legacy Feature Parity Matrix

This document is the cutover gate for the React rebuild. Every row describes behavior that exists in the checked-in legacy system, identifies the exact source evidence, names the intended React replacement, and defines the minimum regression proof. Every row starts as `NOT IMPLEMENTED`; a green build or a visually similar screen does not change that status.

## Source precedence and scope

- `index.html` is the authoritative operator application and `order-form.html` is the authoritative customer order form. Documentation calls `app.html` and `order.html` non-deployment artifact copies, but the current server exposes every HTML file under the content root, so the artifact URLs remain reachable and must be tested (`התקנת-הפרויקט.md:9-14`, `server.js:138-159`).
- `site/index.html`, `site/menu-he.html`, and `site/menu-en.html` are the checked-in marketing/public-site surfaces. Their current behavior, including inert or contradictory behavior, is recorded rather than silently corrected.
- `server.js` and `bm-sync.js` are part of the legacy runtime contract. The same HTML files can also run locally without the server (`README.md:50-58`).
- `CLIENT-REQUIREMENTS-2026-08-12.md` supplements rather than replaces legacy parity. Its rows below record authoritative requested behavior and current legacy divergence; their presence in this matrix does not mean they are implemented.
- “Legacy behavior” means what the source does now, not what the copy claims it does. Rows marked as a legacy limitation still block cutover until an explicit replacement behavior and regression test exist.
- The target names below are component/domain boundaries, not claims that those files already exist.
